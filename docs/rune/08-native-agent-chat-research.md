# Native agent chat research

Zeron revision [ae294f5](https://github.com/zeronsh/zeron/tree/ae294f5342e53e1e25a28165e168bf7d7412b467) is the reference for these findings.

## Desktop composition

Zeron's chat view subscribes to a session, a transcript, and a model catalog. It appends incoming text to the active reply and reconciles message rows when their structure changes. The composer owns each chat's draft and sends the selected model and effort with the message. The sidebar, provider settings, picker, and composer share an agent mark keyed by provider. The terminal has its own lifecycle and UI. [Chat state](https://github.com/zeronsh/zeron/blob/ae294f5342e53e1e25a28165e168bf7d7412b467/apps/zgx/src/chat.rs#L6-L39) · [Composer](https://github.com/zeronsh/zeron/blob/ae294f5342e53e1e25a28165e168bf7d7412b467/apps/zgx/ui/screens/chat/composer.luau#L1-L13) · [Agent marks](https://github.com/zeronsh/zeron/blob/ae294f5342e53e1e25a28165e168bf7d7412b467/apps/zgx/ui/ds/agent_mark.luau) · [Architecture](https://github.com/zeronsh/zeron/blob/ae294f5342e53e1e25a28165e168bf7d7412b467/ARCHITECTURE.md#6-engine-cratesengine-cratesharness-cratesmcp)

Coderune can use the same separation within its Rust application. The agent connector emits typed session, text, completion, and error events. The desktop applies them to its own chat records and reuses its bundled provider logos across surfaces. The provider session ID supplies continuity on subsequent turns and the app-owned transcript gives future capture work a stable integration point.

## Provider entry points

| Agent | Chat and configuration |
| --- | --- |
| Codex | Zeron uses `codex app-server` with newline-delimited JSON on stdio. Initialize the connection, start or resume a thread, then send a turn. Use the display names and per-model effort options from `model/list`. Agent-message deltas carry text, and the turn completion notification marks the end. [Zeron connector](https://github.com/zeronsh/zeron/tree/ae294f5342e53e1e25a28165e168bf7d7412b467/crates/harness/src/codex) · [App Server protocol](https://developers.openai.com/codex/app-server) |
| Claude Code | Zeron uses bidirectional stream JSON. A short-lived initialize request yields a catalog with model values and, where advertised, `supportedEffortLevels`. The documented print mode can also stream text per turn, resume a specific session, and receive model and effort flags. Non-interactive runs can load workspace hooks and MCP servers, so discovery should avoid running workspace hooks and chat should preserve the provider's permission controls. [Zeron catalog probe](https://github.com/zeronsh/zeron/blob/ae294f5342e53e1e25a28165e168bf7d7412b467/crates/harness/src/claude/mod.rs#L815-L903) · [Headless mode](https://code.claude.com/docs/en/headless) · [CLI reference](https://code.claude.com/docs/en/cli-reference) |
| OpenCode | Zeron starts `opencode serve` on a loopback port and consumes the provider's HTTP API and event stream. It handles both API generations and filters events by session. The model catalog supplies variants for models that advertise them. The local 2.0.30 CLI also advertises `opencode run --standalone --format json` with session resumption and `provider/model#variant` selection. [Zeron connector](https://github.com/zeronsh/zeron/blob/ae294f5342e53e1e25a28165e168bf7d7412b467/crates/harness/src/opencode/mod.rs#L15-L59) · [OpenCode API](https://opencode.ai/docs/api) |
| Antigravity | Zeron drives the standalone ACP server. Google also ships `agy acp` which was confirmed by the installed CLI's help. ACP exposes model and thinking-level session config options, with assistant chunks and permission requests delivered through the protocol. [Zeron connector](https://github.com/zeronsh/zeron/tree/ae294f5342e53e1e25a28165e168bf7d7412b467/crates/harness/src/acp) · [Antigravity ACP](https://antigravity.google/docs/cli/acp/) · [ACP session options](https://agentclientprotocol.com/protocol/v1/session-config-options) |

## Installed versions and updates

Zeron's provider rows combine local detection, installed version, and update status. Its engine checks each provider's own release source and considers which installer owns the binary. Codex can be checked against published GitHub releases, Claude Code against its native release channel, and OpenCode against the release source for its major version. Coderune can show a newer version when both versions are known and link to the provider's update instructions.
